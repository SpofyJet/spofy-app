Название — Spofy. Идентификатор приложения — `app.spofy`, ссылки — `spofy://`.

Порядок: Android и Windows, затем iOS. Каждый этап закрывается только проверкой с числом.

## Этапы

1. **Ядро приложения (Go, наш форк Xray).**
   - [x] Разбор и загрузка подписки (`core/internal/sub`).
   - [x] Сборка рабочего конфига из серверного (`core/internal/xcfg`).
   - [x] Движок: запуск и остановка Xray, журнал, счётчики (`core/internal/engine`).
   - [x] Сторож: ядро отдельным процессом, перезапуск после падения (`core/internal/supervisor`).
   - [x] Сторож держит блокировку трафика, пока ядро перезапускается; тест «0 пакетов мимо туннеля» (`core/internal/guard`, на стенде — таблица nft, привязанная к процессу).
   - [x] Замер серверов и выбор лучшего, уход с упавшего сервера (`core/internal/session`). «Подключено» показывается только после ответа через туннель: запрос идёт сразу на два независимых адреса, достаточно одного ответа. Замер идёт в отдельных процессах: по одному ядру на процесс. Без сети сервер не меняется; выбранный человеком сервер сам не меняется никогда. Если не отвечает ни один сервер, туннель не снимается: трафик не идёт мимо, попытки повторяются при каждой проверке.
   - [x] Хранилище (`core/internal/store`): подписка, выбранный сервер, настройки, прошлый замер — один файл, зашифрованный AES-256-GCM. Запись через новый файл и переименование, прошлая копия остаётся; повреждённый файл заменяется прошлой копией, нечитаемые данные не трогаются, пока человек сам не начнёт заново. По прошлому замеру «Авто» подключается сразу, без нового замера; если лучший сервер молчит — замер заново.
   - [x] Канал для интерфейса (`core/internal/ipc`) и слой, который сводит подписку, хранилище и подключение (`core/internal/app`). Строки JSON в обе стороны: ответ приходит, когда действие закончено, ход показывают события. Общие образцы для Go и Dart — `proto/samples/session.jsonl` (24 запроса с ответами и событиями): тест сверяет их с настоящим обменом. Адрес подписки интерфейсу не отдаётся и в тексты ошибок не попадает.
   - [x] Закрытый стенд без интернета (`tools/hermetic.sh`): клиент, два своих сервера, узел между ними и сайт с DNS и подпиской — в пяти сетевых пространствах одного контейнера без сети. Весь путь по каналу интерфейса: подписка, замер, подключение, сайт по имени, прямой сайт, три убийства ядра, молчащий сервер, молчат оба, возврат, обновление подписки, перезапуск, убийство сторожа. Узел считает пакеты и вопросы DNS, ушедшие от клиента мимо туннеля. Идёт в GitHub Actions и в `tools/check.sh`.
   - Выход: `tools/check.sh` зелёный, все мерила этапа с числом.
2. **Интерфейс (Flutter).** Экраны: главный, серверы, подписка, настройки, диагностика. Вид «чернила». Проверка: снимки экранов 360, 390 и окно компьютера сравниваются по пикселям; интерфейс работает с настоящим ядром на Linux.
   - [x] Канал со стороны интерфейса (`app/lib/core`): строгий разбор сообщений, лишнее или незнакомое поле — ошибка. Те же образцы `proto/samples/session.jsonl`, что и у ядра; тест запускает настоящее ядро и сверяет названия состояний с кодом Go.
   - [x] Состояние приложения (`app/lib/state`): снимок от сторожа плюс события; интерфейс сам ничего не хранит.
   - [x] Экраны: главный, серверы, подписка (`app/lib/ui`). Без готовых наборов виджетов: свои кнопки, плитки и значки, шрифт Geologica. Одна залитая кнопка на экран; горящая кнопка — VPN работает. Первый запуск — одна кнопка «Вставить ссылку» из буфера.
   - [x] Проверка: `tools/app-check.sh` — формат, анализатор, 62 теста, 35 снимков по пикселям; идёт в `tools/check.sh` и в GitHub Actions. Листы для просмотра глазами — `tools/sheets.sh`.
   - [x] Настройки, у каждой — действие в ядре, а не только переключатель. «Включать VPN при запуске»: сторож после старта подключается сам. «Без VPN — без интернета»: если серверы молчат уже при включении, туннель и блокировка остаются (раньше в этом случае трафик шёл напрямую). Значения проверяются ядром: не «да/нет» — отказ.
   - [ ] Диагностика.
   - [x] Интерфейс с настоящим ядром на закрытом стенде (`tools/app-stand.sh`): тот же код состояния, что в приложении, запускает ядро, добавляет подписку, замеряет, подключается, меняет сервер без отключения, переживает перезапуск, удаляет подписку. Сайт видит адрес выбранного сервера, мимо туннеля — 0 пакетов.
   - [ ] Память интерфейса.
3. **Android.** Служба VPN отдельным процессом, плитка, автозапуск, выбор приложений.
   - [x] Ядро принимает готовый туннель от системы. Сторож слушает сокет в папке приложения: к нему подключаются и интерфейс, и служба. Служба берёт роль «платформа»; на её вопрос «tun» отвечает дескриптором туннеля, на «untun» убирает своё. Дескриптор уходит в ядро вместе с командой запуска, поэтому смена сервера и перезапуск упавшего ядра идут на том же туннеле, без пересоздания и без окна для утечки. Ядру в этом режиме не нужны права. Отказ системы дать туннель — своя ошибка `guard_failed`, остальные серверы при ней не перебираются. Клиент, который не читает сокет (замороженное приложение), отключается и не тормозит сторож. Проверка — роль службы на закрытом стенде: 20 проверок.
   - [x] Свой пакет исключён из туннеля, маршрут IPv6 идёт в туннель. Трафик IPv6 отдельной проверкой не покрыт.
   - [x] Смена сети не пересоздаёт интерфейс: туннель остаётся, ядро проверяет связь. Служба слушает все сети с интернетом, кроме VPN.
   - [x] Служба закрыта для чужих приложений. Ссылка `spofy://add` только предлагает адрес: добавляет или заменяет подписку человек.
   - [x] Без экрана приложение ничего не опрашивает. Список серверов обновляется по сроку панели и без изменений не скачивается. Связь проверяется по событиям: смена сети, включение экрана, ответы сервера остановились.
   - [x] Запуск системой («Постоянная VPN») и плитка быстрых настроек подключают без интерфейса; в настройках — переход к системным настройкам VPN.
   - [x] Ключ хранилища лежит в Android Keystore.
   - [x] Проверка: сборка и эмулятор в GitHub Actions, размер APK, память, процессор в простое. Код службы проверяется и локально: `tools/android/kotlin-check.sh`.
   - [ ] После подключения по прошлому замеру замер обновляется в фоне.
   - [ ] Выбор приложений.
   - [ ] Подпись выпуска своим ключом.
   - [ ] Расход батареи на настоящем телефоне.
4. **Windows.** Служба с правами, интерфейс без прав, туннель wintun, установщик.
   - Блокировка утечек — фильтры WFP в сеансе процесса: исчезают вместе с ним, правил брандмауэра после аварии не остаётся.
   - Замер серверов при включённом туннеле идёт мимо туннеля (привязка к сетевому интерфейсу). Тогда уход с сервера опирается на свежий замер, а не на прошлый.
   - Блокировка включается до первого подключения и держится до «Отключить».
   - Ключ хранилища защищён DPAPI.
   - Проверка: тесты на машинах Windows в GitHub Actions, 100 аварийных завершений подряд без потери интернета.
5. **Связь со Spofy.** Вход из бота и со страницы подписки одной кнопкой, правило панели для приложения, продление и поддержка внутри, свои коды ошибок в панель.
   - Расход трафика обновляется и тогда, когда подписка не изменилась (ответ 304): проверить, что панель присылает счётчик в таком ответе.
   - Один id на устройство: хеш системного идентификатора с солью приложения. Переживает переустановку, не совпадает у одинаковых моделей, сам идентификатор никуда не передаётся.
6. **Выпуск.** Подпись, обновления со своих серверов с раскаткой 5 → 25 → 100 %, проверка каждой сборки на всех серверах. Обновление ставится только после проверки подписи.
7. **iOS.**

## Самопроверки

- `tools/check.sh`: версия форка совпадает с `core/XRAY_REV`, замены зависимостей форка перенесены, в репозитории нет закрытых файлов, ключей и настоящих значений подписки, образец подписки совпадает с выводом `tools/mkfixture.py`, форматирование, `go vet`, тесты с детектором гонок.
- Образец подписки (19 серверов, все значения выдуманы) проходит загрузку ядром в двух режимах: тест `TestEveryFixtureServerLoads`. Рядом с настоящей подпиской тот же тест проверяет и её.
- Стенд в изолированном контейнере через настоящую ноду, по десятку запросов: `tools/lab.sh inside` (подключение, порты, память, убийство ядра), `tools/lab.sh matrix` (все серверы по разу), `tools/lab.sh leak` (пакеты мимо туннеля, убийство сторожа), `tools/lab.sh measure 4` (замер всех серверов), `tools/lab.sh failover` (блокировка рабочего сервера дважды подряд, затем всех серверов сразу), `tools/lab.sh state` (повторные подключения, повреждённый файл, чужой ключ), `tools/lab.sh serve` (весь путь по каналу интерфейса: подписка, замер, подключение, убийство ядра, обновление подписки, перезапуск).
- Закрытый стенд `tools/hermetic.sh` не требует ни интернета, ни настоящих серверов: 62 проверки за 109 с на каждый коммит. Проверено, что он ловит утечку: без блокировки трафика падают 4 проверки.
- `tools/app-check.sh`: форматирование, анализатор, тесты интерфейса и сверка снимков экранов по пикселям в контейнере с той же версией Flutter, что в GitHub Actions. Падение любого теста останавливает проверку.
- `tools/app-stand.sh`: код состояния интерфейса управляет настоящим ядром и настоящим туннелем на том же закрытом стенде, без интернета.
- Эмулятор Android в GitHub Actions (`tools/android/emulator.py`): свои два сервера и панель на машине сборки, приложение ставится и проходит весь путь — подписка, подключение, чужое приложение через туннель, смена сервера, убийство ядра, замолчавший сервер, Wi-Fi и режим полёта, запуск системой, плитка, ссылка; снимки экранов и журнал устройства сохраняются.
- `tools/android/kotlin-check.sh`: код службы компилируется против платформы Android и оболочки Flutter тех же версий, 5 с.
- Каждая найденная ошибка сначала становится тестом.

Когда заблокированы все серверы, туннель остаётся, прямые сайты открываются, после разблокировки связь возвращается за 0,2–0,9 с. Журнал соединений в ядре выключен.
- 19.11.2026. Хранилище. Повторное подключение «Авто» по сохранённому замеру — 0,11–0,12 с вместо 2,1 с. Повреждённый файл заменяется прошлой копией, с чужим ключом файлы остаются как были.
- 19.11.2026. Канал для интерфейса. Весь путь через настоящие серверы по сообщениям JSON: подписка, замер, подключение за 0,11 с, смена сервера за 0,26 с, ядро убито — связь подтверждена снова, после перезапуска всё на месте.
- 19.11.2026. Закрытый стенд без интернета: 27 проверок за 25 с, идёт на каждый коммит. Стенд нашёл ошибку: ответ быстрее 1 мс считался неизвестной задержкой, и уход с молчащего сервера ждал 9 с вместо 5. Этап 1 закрыт.
- 19.11.2026. Этап 2 начат. Интерфейс разбирает канал по тем же образцам, что и ядро, и проверен с настоящим ядром. Экраны главный, серверы и подписка сверяются по 24 снимкам. Просмотр глазами нашёл и убрал: повтор сервера и задержки на главном, сдвиг кнопки между загрузкой и готовым экраном на 1,7 px, обрезанные тексты на 320 px при шрифте 130 %.
- 19.11.2026. Интерфейс проверен с настоящим ядром на закрытом стенде: весь путь от подписки до смены сервера и перезапуска, 0 пакетов мимо туннеля.
- 19.11.2026. Настройки. Тест строгого режима нашёл пробел: если на замер при включении не отвечал ни один сервер, туннель не поднимался и трафик шёл напрямую. Теперь сторож поднимает туннель на первом сервере и держит блокировку; на стенде 0 пакетов мимо.
- 19.11.2026. Этап 3 начат. Ядро принимает готовый туннель от системы, как его даёт служба VPN Android; стенд играет роль службы. Стенд нашёл две ошибки до первой сборки под Android: движок, проверяя свой вход, переводил его в неблокирующий режим и сразу выходил; отказ системы дать туннель показывался как «сервер не отвечает», и сторож перебирал остальные серверы.
- 19.11.2026. Android на эмуляторе. Приложение проходит весь путь на Android 14. Эмулятор нашёл то, чего не видел стенд: система называет владельцу VPN «сетью по умолчанию» его же VPN, и потеря Wi-Fi не была видна — служба теперь слушает сети вне VPN; ответы местного DNS и прямых сайтов скрывали молчание сервера — детектор считает только ответы серверов; Android стучится на адрес DNS туннеля по порту шифрованного DNS, и эти попытки уходили на сервер — теперь отклоняются на устройстве; «Нет сети» появлялось через 10 с — теперь сразу; ссылка при холодном запуске терялась, если подписка уже есть.
- 19.11.2026. Список серверов обновляется сам: по сроку панели, после неудачного подключения — сразу. Работающее соединение не трогается, пока настройки его сервера те же. При уходе с сервера замеряются и те серверы, что при подключении не замерялись.
