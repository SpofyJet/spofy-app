# Приложение Spofy: план

Название — Spofy. Идентификатор приложения — `app.spofy`, ссылки — `spofy://`.

Порядок: Android и Windows, затем iOS. Каждый этап закрывается только проверкой с числом.

## Этапы

1. **Ядро приложения (Go, наш форк Xray).**
   - [x] Разбор и загрузка подписки (`core/internal/sub`).
   - [x] Сборка рабочего конфига из серверного (`core/internal/xcfg`).
   - [x] Движок: запуск и остановка Xray, журнал, счётчики (`core/internal/engine`).
   - [x] Сторож: ядро отдельным процессом, перезапуск после падения (`core/internal/supervisor`).
   - [x] Сторож держит блокировку трафика, пока ядро перезапускается; тест «0 пакетов мимо туннеля» (`core/internal/guard`, на стенде — таблица nft, привязанная к процессу).
   - [x] Замер серверов и выбор лучшего, уход с упавшего сервера (`core/internal/session`). «Подключено» показывается только после ответа через туннель: запрос идёт сразу на два независимых адреса, достаточно одного ответа. Замер идёт в отдельных процессах: по одному ядру на процесс. Без сети сервер не меняется; выбранный человеком сервер сам не меняется никогда. Если не отвечает ни один сервер, туннель не снимается: трафик не идёт мимо, попытки повторяются при каждой проверке.
   - [x] Хранилище (`core/internal/store`): подписка, выбранный сервер, настройки, прошлый замер — один файл, зашифрованный AES-256-GCM. Запись через новый файл и переименование, прошлая копия остаётся; повреждённый файл заменяется прошлой копией, нечитаемые данные не трогаются, пока человек сам не начнёт заново. По прошлому замеру «Авто» подключается сразу, без нового замера; если лучший сервер молчит — замер заново.
   - [x] Канал для интерфейса (`core/internal/ipc`) и слой, который сводит подписку, хранилище и подключение (`core/internal/app`). Строки JSON в обе стороны: ответ приходит, когда действие закончено, ход показывают события. Общие образцы для Go и Dart — `proto/samples/session.jsonl` (24 запроса с ответами и событиями): тест сверяет их с настоящим обменом. Адрес подписки интерфейсу не отдаётся и в тексты ошибок не попадает.
   - [x] Закрытый стенд без интернета (`tools/hermetic.sh`): клиент, два своих сервера, узел между ними и сайт с DNS и подпиской — в пяти сетевых пространствах одного контейнера без сети. Весь путь по каналу интерфейса: подписка, замер, подключение, сайт по имени, прямой сайт, три убийства ядра, молчащий сервер, молчат оба, возврат, обновление подписки, перезапуск, убийство сторожа. Узел считает пакеты и вопросы DNS, ушедшие от клиента мимо туннеля. Идёт в GitHub Actions и в `tools/check.sh`.
   - Выход: `tools/check.sh` зелёный, все мерила этапа с числом.
2. **Интерфейс (Flutter).** Экраны: главный, серверы, подписка, настройки, диагностика. Вид «чернила». Проверка: снимки экранов 360, 390 и окно компьютера сравниваются по пикселям; интерфейс работает с настоящим ядром на Linux.
   - [x] Канал со стороны интерфейса (`app/lib/core`): строгий разбор сообщений, лишнее или незнакомое поле — ошибка. Те же образцы `proto/samples/session.jsonl`, что и у ядра; тест запускает настоящее ядро и сверяет названия состояний с кодом Go.
   - [x] Состояние приложения (`app/lib/state`): снимок от сторожа плюс события; интерфейс сам ничего не хранит.
   - [x] Экраны: главный, серверы, подписка (`app/lib/ui`). Без готовых наборов виджетов: свои кнопки, плитки и значки, шрифт Geologica. Одна залитая кнопка на экран; горящая кнопка — VPN работает. Первый запуск — одна кнопка «Вставить ссылку» из буфера.
   - [x] Проверка: `tools/app-check.sh` — формат, анализатор, 73 теста, 42 снимка по пикселям; идёт в `tools/check.sh` и в GitHub Actions. Листы для просмотра глазами — `tools/sheets.sh`.
   - [x] Настройки, у каждой — действие в ядре, а не только переключатель. «Включать VPN при запуске»: сторож после старта подключается сам. «Без VPN — без интернета»: если серверы молчат уже при включении, туннель и блокировка остаются (раньше в этом случае трафик шёл напрямую). Значения проверяются ядром: не «да/нет» — отказ.
   - [x] Поддержка: отчёт для разбора жалобы — версия, система и устройство, срок и трафик подписки, настройки, состояние, задержка каждого сервера и журнал 40 последних изменений подключения со временем и кодом. Журнал ведёт ядро. Адреса подписки и адресов серверов в отчёте нет: это проверяют тест и стенд. Отчёт копируется одной кнопкой, вторая открывает поддержку.
   - [x] Интерфейс с настоящим ядром на закрытом стенде (`tools/app-stand.sh`): тот же код состояния, что в приложении, запускает ядро, добавляет подписку, замеряет, подключается, меняет сервер без отключения, переживает перезапуск, удаляет подписку. Сайт видит адрес выбранного сервера, мимо туннеля — 0 пакетов.
   - [x] Подписка, которая не даёт серверов. Панель в таком случае присылает строки-заглушки без адреса; приложение не показывает их как серверы, а называет причину — закончилась, кончился трафик, заняты все места — и ведёт на страницу подписки одной кнопкой: «Продлить подписку», «Докупить трафик», «Добавить устройство». Работающий VPN при этом выключается, интернет остаётся открытым, чтобы можно было оплатить. После возврата в приложение список запрашивается снова сам. На экране подписки та же кнопка есть всегда.
   - [x] Строки панели без адреса рядом с серверами («в тарифе нет этих серверов», «сменить тариф») стоят одной строкой в конце списка серверов; нажатие открывает бот или сайт, названный в тексте, иначе страницу подписки.
   - [x] Ссылка подписки работает без настройки панели под приложение: если по адресу пришёл список ссылок, а не конфиги, ядро запрашивает тот же адрес в виде JSON и дальше ходит уже туда. Сверено на двух тестовых аккаунтах: ответ совпадает до байта с тем, что получают клиенты, которых панель знает.
   - [ ] Память интерфейса.
3. **Android.** Служба VPN отдельным процессом, плитка, автозапуск, выбор приложений.
   - [x] Ядро принимает готовый туннель от системы. Сторож слушает сокет в папке приложения: к нему подключаются и интерфейс, и служба. Служба берёт роль «платформа»; на её вопрос «tun» отвечает дескриптором туннеля, на «untun» убирает своё. Дескриптор уходит в ядро вместе с командой запуска, поэтому смена сервера и перезапуск упавшего ядра идут на том же туннеле, без пересоздания и без окна для утечки. Ядру в этом режиме не нужны права. Отказ системы дать туннель — своя ошибка `guard_failed`, остальные серверы при ней не перебираются. Клиент, который не читает сокет (замороженное приложение), отключается и не тормозит сторож. Проверка — роль службы на закрытом стенде: 20 проверок.
   - [x] Свой пакет исключён из туннеля, маршрут IPv6 идёт в туннель. На эмуляторе Android 14 соединение по IPv6 из чужого приложения приходит на сервер через туннель и ни разу мимо; у эмулятора Android 7.0 пути IPv6 нет, там проверка пропускается.
   - [x] Смена сети не пересоздаёт интерфейс: туннель остаётся, ядро проверяет связь. Служба слушает все сети с интернетом, кроме VPN.
   - [x] Служба закрыта для чужих приложений. Ссылка `spofy://add` только предлагает адрес: добавляет или заменяет подписку человек.
   - [x] Без экрана приложение ничего не опрашивает. Список серверов обновляется по сроку панели и без изменений не скачивается. Связь проверяется по событиям: смена сети, включение экрана, ответы сервера остановились.
   - [x] Запуск системой («Постоянная VPN») и плитка быстрых настроек подключают без интерфейса; в настройках — переход к системным настройкам VPN.
   - [x] Ключ хранилища лежит в Android Keystore.
   - [x] Проверка: сборка и эмулятор в GitHub Actions, размер APK, память, процессор в простое. Код службы проверяется и локально: `tools/android/kotlin-check.sh`.
   - [x] После подключения по прошлому замеру замер обновляется в фоне: если ему больше часа — через 10 с после подключения и при проверке связи, одним процессом, мимо туннеля. Сервер не меняется; новый замер получают следующее подключение и порядок запасных серверов.
