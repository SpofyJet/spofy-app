# Приложение Spofy: план

Название — Spofy. Идентификатор приложения — `app.spofy`, ссылки — `spofy://`.

Порядок: Android и Windows, затем iOS. Каждый этап закрывается только проверкой с числом.

## Этапы

1. **Ядро приложения (Go, наш форк Xray).**
   - [x] Разбор и загрузка подписки (`core/internal/sub`).
   - [x] Сборка рабочего конфига из серверного (`core/internal/xcfg`).
   - [x] Движок: запуск и остановка Xray, журнал, счётчики (`core/internal/engine`).
   - [x] Сторож: ядро отдельным процессом, перезапуск после падения (`core/internal/supervisor`).
   - [x] Сторож держит блокировку трафика, пока ядро перезапускается; тест «0 пакетов мимо туннеля» (`core/internal/guard`, на стенде — таблица nft, привязанная к процессу).
   - [x] Замер серверов и выбор лучшего, уход с упавшего сервера (`core/internal/session`). «Подключено» показывается только после ответа через туннель: запрос идёт сразу на два независимых адреса, достаточно одного ответа. Замер идёт в отдельных процессах: по одному ядру на процесс. Без сети сервер не меняется; выбранный человеком сервер сам не меняется никогда. Если не отвечает ни один сервер, туннель не снимается: трафик не идёт мимо, попытки повторяются при каждой проверке.
   - [x] Хранилище (`core/internal/store`): подписка, выбранный сервер, настройки, прошлый замер — один файл, зашифрованный AES-256-GCM. Запись через новый файл и переименование, прошлая копия остаётся; повреждённый файл заменяется прошлой копией, нечитаемые данные не трогаются, пока человек сам не начнёт заново. По прошлому замеру «Авто» подключается сразу, без нового замера; если лучший сервер молчит — замер заново.
   - [x] Канал для интерфейса (`core/internal/ipc`) и слой, который сводит подписку, хранилище и подключение (`core/internal/app`). Строки JSON в обе стороны: ответ приходит, когда действие закончено, ход показывают события. Общие образцы для Go и Dart — `proto/samples/session.jsonl` (24 запроса с ответами и событиями): тест сверяет их с настоящим обменом. Адрес подписки интерфейсу не отдаётся и в тексты ошибок не попадает.
   - [x] Закрытый стенд без интернета (`tools/hermetic.sh`): клиент, два своих сервера, узел между ними и сайт с DNS и подпиской — в пяти сетевых пространствах одного контейнера без сети. Весь путь по каналу интерфейса: подписка, замер, подключение, сайт по имени, прямой сайт, три убийства ядра, молчащий сервер, молчат оба, возврат, обновление подписки, перезапуск, убийство сторожа. Узел считает пакеты и вопросы DNS, ушедшие от клиента мимо туннеля. Идёт в GitHub Actions и в `tools/check.sh`.
   - Выход: `tools/check.sh` зелёный, все мерила этапа с числом.
2. **Интерфейс (Flutter).** Экраны: главный, серверы, подписка, настройки, диагностика. Вид «чернила». Проверка: снимки экранов 360, 390 и окно компьютера сравниваются по пикселям; интерфейс работает с настоящим ядром на Linux.
   - [x] Канал со стороны интерфейса (`app/lib/core`): строгий разбор сообщений, лишнее или незнакомое поле — ошибка. Те же образцы `proto/samples/session.jsonl`, что и у ядра; тест запускает настоящее ядро и сверяет названия состояний с кодом Go.
   - [x] Состояние приложения (`app/lib/state`): снимок от сторожа плюс события; интерфейс сам ничего не хранит.
   - [x] Экраны: главный, серверы, подписка (`app/lib/ui`). Без готовых наборов виджетов: свои кнопки, плитки и значки, шрифт Geologica. Одна залитая кнопка на экран; горящая кнопка — VPN работает. Первый запуск — одна кнопка «Вставить ссылку» из буфера.
   - [x] Проверка: `tools/app-check.sh` — формат, анализатор, 104 теста, 61 снимок по пикселям; идёт в `tools/check.sh` и в GitHub Actions. Листы для просмотра глазами — `tools/sheets.sh`.
   - [x] Настройки, у каждой — действие в ядре, а не только переключатель. «Включать VPN при запуске»: сторож после старта подключается сам. «Без VPN — без интернета»: если серверы молчат уже при включении, туннель и блокировка остаются (раньше в этом случае трафик шёл напрямую). Значения проверяются ядром: не «да/нет» — отказ.
   - [x] Поддержка: отчёт для разбора жалобы — версия, система и устройство, срок и трафик подписки, настройки, состояние, задержка каждого сервера и журнал 40 последних изменений подключения со временем и кодом. Журнал ведёт ядро. Адреса подписки и адресов серверов в отчёте нет: это проверяют тест и стенд. Отчёт копируется одной кнопкой, вторая открывает поддержку.
   - [x] Интерфейс с настоящим ядром на закрытом стенде (`tools/app-stand.sh`): тот же код состояния, что в приложении, запускает ядро, добавляет подписку, замеряет, подключается, меняет сервер без отключения, переживает перезапуск, удаляет подписку. Сайт видит адрес выбранного сервера, мимо туннеля — 0 пакетов.
   - [x] Подписка, которая не даёт серверов. Панель в таком случае присылает строки-заглушки без адреса; приложение не показывает их как серверы, а называет причину — закончилась, кончился трафик, заняты все места — и ведёт на страницу подписки одной кнопкой: «Продлить подписку», «Докупить трафик», «Добавить устройство». Работающий VPN при этом выключается, интернет остаётся открытым, чтобы можно было оплатить. После возврата в приложение список запрашивается снова сам. На экране подписки та же кнопка есть всегда.
   - [x] Строки панели без адреса рядом с серверами («в тарифе нет этих серверов», «сменить тариф») стоят одной строкой в конце списка серверов; нажатие открывает бот или сайт, названный в тексте, иначе страницу подписки.
   - [x] Ссылка подписки работает без настройки панели под приложение: если по адресу пришёл список ссылок, а не конфиги, ядро запрашивает тот же адрес в виде JSON и дальше ходит уже туда. Сверено на двух тестовых аккаунтах: ответ совпадает до байта с тем, что получают клиенты, которых панель знает.
   - [x] Несколько подписок и свои ключи; серверы по стране и общему имени, протокол над именем, поиск, порядок по скорости или стране (решения 57, 58).
   - [x] Настройки проверки серверов и туннеля, журнал, «О приложении» с версией, сборкой, ядром, устройством и лицензиями (решение 59).
   - [x] Таймер «VPN работает» на главном (решение 60).
   - [x] Тема («Системная», «Светлая», «Тёмная») и язык («Системный», «Русский», «English») в разделе «Интерфейс» настроек; выбор хранит ядро, его видят окно, трей и служба Android; смена перекрашивает и переписывает открытые экраны сразу (решения 61–65).
   - [x] Круглые флаги стран вместо букв в списке серверов и на главном; картинки и список кодов делает `tools/flags.sh` из набора flag-icons (решение 67).
   - [x] Напоминание о конце подписки за 1, 3, 5 или 7 дней и в день конца, на Android и в трее Windows; выбор — в настройках «Уведомления» (решение 69).
   - [x] Переехавшая подписка идёт за новым адресом, закрытая у оператора — через работающий сервер; молчащие серверы помечены; пустой экран ведёт в магазин и поддержку (решение 68).

Эмулятор нашёл то, чего не видел стенд: система называет владельцу VPN «сетью по умолчанию» его же VPN, и потеря Wi-Fi не была видна — служба теперь слушает сети вне VPN; ответы местного DNS и прямых сайтов скрывали молчание сервера — детектор считает только ответы серверов; Android стучится на адрес DNS туннеля по порту шифрованного DNS, и эти попытки уходили на сервер — теперь отклоняются на устройстве; «Нет сети» появлялось через 10 с — теперь сразу; ссылка при холодном запуске терялась, если подписка уже есть.
- 19.11.2026. Список серверов обновляется сам: по сроку панели, после неудачного подключения — сразу. Работающее соединение не трогается, пока настройки его сервера те же. При уходе с сервера замеряются и те серверы, что при подключении не замерялись.
- 20.11.2026. Выбор приложений и состав ядра. Приложение, убранное из VPN, идёт мимо туннеля, остальные — через него; смена выбора на ходу — новый туннель за 0,2 с на стенде и 0,6–0,7 с на эмуляторе, 0 пакетов мимо. Ядро собирается из явного списка частей форка без консольных команд и загрузчиков TOML и YAML, таблица перемещений упакована: APK 19,1 → 18,6 МБ, ядро после установки 34,3 → 30,5 МБ, все 19 серверов подключаются. Повтор прошлого коммита на другой машине сборки показал, что холодный запуск «плавает» от 0,74 до 1,40 с без правок кода — к замеру добавлен контрольный цикл на устройстве.
- 20.11.2026. Замер в фоне и чистое завершение. Замеру больше часа — сторож перемеряет серверы за работающим туннелем, не меняя сервер. Сборка в GitHub Actions поймала редкую гонку: фоновая загрузка списка могла дописывать файл после остановки сторожа; теперь остановка дожидается фоновых задач, тест это проверяет.
- 20.11.2026. Android 7 и сторожа за самими проверками. Сценарий эмулятора идёт на двух системах сразу: Android 14 и Android 7.0; сборка APK — отдельная задача, эмуляторы берут её файлы. На Android 7.0 прошло всё, включая ядро с упакованной таблицей перемещений. Нашлась проверка, которая не могла упасть (локальное имя закрывало список запросов), — теперь это ловит `tools/pycheck.py`. Опыт с соединениями мимо туннеля объяснил «медленные» проверки связи на Android 14: это виртуальный Wi-Fi эмулятора.
- 20.11.2026. Поддержка. В настройках появился экран с отчётом для разбора жалоб; журнал подключений ведёт ядро. На экране выбора приложений — предупреждение о системной блокировке соединений без VPN.
- 20.11.2026. Старые системы и свежие зависимости. Эмулятор Android 7.0 показал, что её набор доверенных центров не знает сертификатов подписки, серверов и DNS: приложение теперь несёт три центра с собой, и доверие проверяется на обеих системах. Трафик IPv6 проверен соединением: на сервер приходит через туннель. Flutter 3.50.1, AGP 9.5.1, Gradle 9.9.2, Kotlin 2.4.21 — снимки экранов совпали до пикселя, оба эмулятора прошли. Выпуск подписывается своим ключом.
- 20.11.2026. Закончившаяся подписка. Запрос настоящей подписки показал то, чего не было ни в одном образце: вместо серверов панель присылает шесть строк с текстом, и приложение показало бы их как серверы. Теперь это отдельное состояние с кнопкой оплаты; стенд проверяет, что туннель снят, интернет открыт и после оплаты подключение идёт без ручного обновления. Заодно найдено, что служба Android при отказе ядра оставалась с уведомлением «Подключаемся». Собранное ядро проверено на настоящей странице подписки: рабочий аккаунт — 18 серверов, закончившийся — причина и отказ в подключении; новых устройств в панели не появилось. Страница не отдаёт метку версии списка, поэтому обновление раз в час скачивает его целиком: 12 КБ в сжатом виде.
- 20.11.2026. Записи без ответа. В списке сервиса у большинства людей есть строки с текстом, которые выглядят как серверы и никогда не отвечают; так же ведёт себя любой упавший сервер. Замер перед первым подключением ждал их до предела: 4,0 с вместо 0,2. Теперь выбор делается, как только ни один незаконченный замер уже не может выиграть: все начаты, и каждый идёт дольше двух времён лучшего ответа плюс 0,1 с. Серверы запасного яруса замеряются до выбора и остаются в запасе; лучший ярус по-прежнему ждём до конца. Кнопка «Замерить» ждёт всех, но показывает задержки по мере ответов. Сами строки с текстом пока показываются в списке как серверы без ответа — так же, как в других приложениях.
- 20.11.2026. Windows, первый шаг. Ядро и раньше собиралось под Windows, но ни разу там не запускалось. Теперь его тесты идут на машине Windows (с первого раза упали только три проверки «файл закрыт», дело было в самих проверках), туннель поднимается за секунду, а блокировка сторожа на фильтрах WFP держит: 100 убийств ядра подряд, 52 569 попыток отправить запрос мимо туннеля — 0 прошло. Найдено по дороге: после пяти падений за минуту сторож сдаётся и подключение поднимается заново до 21,7 с — блокировка всё это время стоит.
- 20.11.2026. Windows, второй шаг: служба и канал. Интерфейс без прав говорит со службой через именованный канал; права на канал проверены по записям — людям за компьютером только чтение и запись, без права встать на место службы (обычное право записи его включает, поэтому выдано не оно). Папку состояния, подменённую ссылкой или созданную кем-то заранее, служба отодвигает и создаёт свою. На стенде: подключение через службу 0,4 с, убитая служба возвращает туннель за 3,7 с. Слабое место — около секунды без блокировки, пока служба поднимается; это следующий шаг.
- 20.11.2026. Android 7.0 и значок. После смены выбора приложений Android 7.0 включает новый туннель в сеть через 0,02–0,1 с после того, как его выдал; ядро брало его сразу, и вторая смена в этот промежуток оставляла VPN без интернета до переподключения. Теперь до Android 10 служба отдаёт туннель ядру, когда система его приняла (ждёт до 1,5 с); проверка на эмуляторе 7.0 снова проходит вся. Значок приложения был стандартным значком Flutter — теперь это логотип Spofy на синем, как у кабинета на главном экране.
- 20.11.2026. Windows, третий шаг: окно и блокировка, переживающая службу. Окно Spofy говорит со службой по каналу и показывает её состояние; закрытое окно VPN не выключает. С «Без VPN — без интернета» блокировка остаётся, когда службу убили или остановили: на стенде 0 запросов мимо туннеля. Найдено по дороге: снятие блокировки удаляло правила в случайном порядке, и на миг запрет оставался без разрешений — соседние программы получали отказ даже на 127.0.0.1, теперь сначала снимается запрет; часы Go на Windows идут шагами 0,5–15,6 мс, и быстрый замер выходил нулевым — замеры теперь по счётчику производительности; код ошибки из Dart через GetLastError ненадёжен — канал читает и пишет через NtReadFile и NtWriteFile; окно не закрывалось, пока потоки канала ждали данных, — теперь при закрытии сначала закрывается канал. Служба после сбоя поднимается через 1, 2, 5 с вместо 1, 5, 30.
- 20.11.2026. Сборка на самом новом. JDK сборки 21 → 27 (последний выпуск, Gradle 9.9 его поддерживает), плагин Android 9.5.1 → 9.5.2; Kotlin 2.4.21 и Gradle 9.9.2 и так последние, Kotlin 2.5.0 пока кандидат — переход в день выпуска. Уровень байткода остаётся 17: это Java самого Android 14 и новее, выше телефонам ничего не даёт. APK тех же размеров (18,7 / 18,9 / 19,9 МБ), оба эмулятора прошли.
- 20.11.2026. Windows: падение ядра и смена сервера. Wintun привязывает адаптер к тому, кто его создал, а создавало его ядро: падение ядра уносило адаптер, и Windows заводила интерфейс заново — 6 пересозданий на 10 смен сервера с паузой до 8,3 с, после убийства ядра запросы имён ждали до 12 с, худший возврат 22,6 с. Теперь адаптер на всё подключение держит служба, ядро его открывает. Второе: ядро настраивало интерфейс, стирая все его маршруты и ставя заново. Windows сама добавляет к нашим маршрутам и адресу свои, например маршрут широковещательного адреса подсети, и убирает их вместе с нашими; стирание натыкалось на уже убранные и ждало 1 с — в 91 из 100 перезапусков. Теперь ядро сравнивает, что есть, с тем, что нужно, и меняет только свои маршруты; это поймала проверка на настоящем адаптере. Итог на 100 убийствах ядра: ядро снова работает через 62–130 мс вместо 1,1 с, повторов настройки 0, худший возврат 2,3 с вместо 22,6 с, мимо туннеля 0 из 15 770 запросов; смена сервера 0,05–0,1 с. Найдено по дороге: собственные проверки форка ядра давно были красными — две программы стенда в одном пакете ломали сборку тестов на всех системах, три файла не по формату, тест перезагрузки сертификата на Windows падал, если удалял файл в момент чтения; теперь зелёные на Linux, macOS и Windows. Один обычный прогон упал целиком: машина сборки перестала открывать сайт проверки даже напрямую, без туннеля; тот же коммит в тяжёлом прогоне прошёл всё. Его повтор дал одну смену сервера за 5,08 с из 40: ядро Xray отправляло запрос DNS по UDP один раз и ждало 4 с, а одинаковые запросы склеивало, поэтому один потерянный пакет держал и проверку связи, и программы. Теперь ядро повторяет запрос через 1 и 2 с: потеря стоит 1 с; 110 смен сервера — не дольше 0,11 с. Стенд теперь требует, чтобы обычная смена (медиана) укладывалась в 0,5 с, а число смен задаётся при ручном запуске.
- 20.11.2026. Windows: значок в области уведомлений. Своя небольшая программа на Go рядом со службой, а не часть окна: окно можно закрыть целиком, а значок остаётся и стоит 14 МБ памяти. Стенд нашёл гонку в протоколе: событие могло уйти раньше ответа на приветствие и оказаться новее снимка в нём — снимок теперь берётся под той же блокировкой, что и запись событий; это касается и окна. Стенд управляет значком через настоящее меню, как человек: открывает его, читает подписи и выбирает пункт.
- 20.11.2026. Ни одной двери к ядру. Разборы 2026 года показали, как приложения на устройстве находят VPN: локальный прокси без пароля, API ядра, которое отдаёт серверы, и открытый всем канал управления. У нас API и входы кроме туннеля и раньше выбрасывались из конфигурации; теперь из программы убран и сам режим локального прокси, а тест проверяет это на всех образцах серверов. Служба Windows отвечает только своим программам, системе и администраторам — на стенде программа с правами человека получает отказ.
- 21.11.2026. Windows: установщик. Вместо Inno Setup — своя программа на Go (решение 54): 21,2 МБ, распаковка 2,6–3,6 с, при сбое новой службы на диске все файлы прежней версии. Стенд нашёл, что папку состояния, созданную установщиком, служба принимала за чужую и убирала; теперь её владелец — администраторы.
- 21.11.2026. Дыра в выборе приложений на Android. Разбор приложений, которые ищут VPN на устройстве, натолкнул на проверку: приложение, убранное из VPN, может привязать сокет к интерфейсу туннеля, и на Android 14 проба так дошла до сервера. Ядро теперь сверяет владельца каждого нового соединения в туннеле с системой (решение 55): проба получает отказ, у приложений внутри VPN отказов 0, ответ системы около 1 мс; DNS системы идёт мимо туннеля, и частный DNS работает в режиме «только выбранные».
- 21.11.2026. Обновления, настройки, журнал, серверы по странам с протоколом, несколько подписок, таймер (решения 56–60). - 21.11.2026. Светлая тема и английский язык (решения 61–65). Светлая палитра — тот же вид: каждый цвет текста на каждом основании не ниже 4,5:1 по WCAG, это проверяет тест. Без выбора тема и язык — как в системе и меняются вместе с ней; выбранные хранит ядро, поэтому трей Windows и уведомление Android говорят на языке окна. Тёмные русские снимки после переделки совпали до пикселя; два снимка нижней части настроек сдвинулись на новый раздел «Интерфейс».
- 21.11.2026. Контраст тёмной темы. Тест WCAG, написанный для светлой палитры, нашёл, что тихий цвет тёмной — заголовки разделов, подсказки, строка протокола — давал 3,13–4,08:1 при нужных 4,5. Теперь #8290A5: 4,60–5,99 (решение 66); 45 снимков перерисованы, меняются только эти подписи.
- 21.11.2026. Флаги стран (решение 67). Буквы «NL», «DE» в списке серверов и на главном заменены круглыми флагами: 257 картинок WebP по 102 px, 272,8 КБ, около 325 КБ в APK. Формат и размер выбраны замером на всех флагах: WebP почти без потерь на 44 % меньше PNG без потерь при худшем флаге 43,7 дБ, а WebP с потерями больше и размывает цветные края. Замер нашёл, что флаг, нарисованный сразу в нужном размере, получает полупрозрачную нить на стыке полос (44 флага, до 29 %), — флаги рисуются в 8 раз крупнее и уменьшаются усреднением, нить не больше 5 %.
- 21.11.2026. Выпуск 0.2.0.
